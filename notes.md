3. SPAKE2 is implemented via `github.com/backkem/spake2-go` (RFC 9382, MIT, published May 2025). The library was chosen because `bytemare/spake2` (the originally planned package) does not exist. `backkem/spake2-go` uses a 4-message exchange — Start → Exchange → Finish → Confirm — rather than the 2-message design described in the plan; this is because it includes key confirmation built into the protocol. If you want to implement SPAKE2 manually later, the relevant code lives in `internal/identity/ephemeral.go`. The wire messages are already agnostic to the library (raw `[]byte` payloads over the relay channel), so swapping the implementation only requires changing `ephemeral.go`.
